# 精准绑定路由上游密钥

`PUT /api/gateway/groups/{group_id}/routes/{route_id}/key` 在已有路由上绑定一把明确指定的上游密钥，沿用管理端 Bearer Token 鉴权。

请求体只接受一个正整数字段，不接受重复字段、未知字段、多个 JSON 对象或大于 4 KiB 的正文：

```json
{"source_api_key_id": 123}
```

成功返回 `200` 和更新后的路由对象；响应不包含密钥明文或密文。只修改该路由的密钥 ID、名称、加密内容及更新时间，不保存整组路由，也不调整其他路由、上游密钥、模型映射、倍率或启停状态。

## 安全调用流程

1. 读取目标组和路由，确认路由 ID、渠道 ID、源分组 ID/名称。业务编号与数据库 ID 不能混用。
2. 通过该渠道的密钥列表找到要绑定的具体密钥 ID。Sub2API 按源分组 ID 匹配；NewAPI 按源分组名称匹配。同名密钥不能代替 ID 匹配。
3. 没有合适密钥时，先通过现有 `POST /api/channels/{channel_id}/api-keys` 明确创建专用密钥，确认创建结果及 ID 后再调用本接口。本接口不会创建、重命名、启用或修改任何上游密钥。
4. 调用上述单路由接口，回读路由，确认返回的 `source_api_key_id` 与预期一致。需要更新模型目录时，再单独预览并同步模型。

服务端会检查密钥属于该渠道的目标源分组、状态及有效期，并完整核验密钥分页。上游查询失败、分页不完整或身份无法确认时拒绝绑定，不按名称猜测、不降级选择其他密钥。读取上游期间如路由发生并发修改，绑定失败，保留并发修改结果。

| HTTP 状态 | 含义与处理 |
| --- | --- |
| `400` | 请求体非法，或密钥、源分组、状态、有效期、分页等校验失败。错误不包含上游原始响应或密钥。 |
| `401` | 未通过管理员认证。 |
| `404` | 组或路由不存在，或路由不属于指定组。 |
| `409` | 读取上游期间路由已变化；重新读取并确认目标后重试。 |
| `500` | 内部存储或加密错误；检查服务日志，不盲目重试写入。 |

## 与批量补齐接口的区别

`POST /api/gateway/groups/{group_id}/routes/ensure-keys` 仅补齐启用且缺少密钥绑定的路由，跳过停用路由和已绑定路由。补齐时不更新任何已有上游密钥的名称、分组、状态或限额。

补齐前读取完整分页，只复用稳定名称唯一且来源匹配的密钥；没有候选时才创建专用密钥。同名异组、重复名称、分页失败或返回掩码都不会通过修改旧密钥来修复。创建后还会完整回读验证；若后续读取或绑定失败，新建密钥保留并在结果中提示 ID，重试时重新核查并复用，不自动删除。

同一服务实例的绑定与补齐操作串行执行，防止并发重复创建；这不是分布式锁。多个实例或供应商返回不一致目录时不保证恰好创建一次。创建超时或结果不明确时，先核查上游稳定名称密钥，不盲目重复创建。

存储更新校验原路由来源、原绑定和更新时间；MySQL 的整组保存锁定原路由快照，避免把并发的新绑定写回成旧密钥。源分组 ID 变化会清除旧绑定；同 ID 改名会保留。两边都没有 ID 时才以去除首尾空白的名称判断同源。

指定某一条路由绑定或更换密钥时，使用新的单路由接口。不要用整组 `PUT /routes` 或 `ensure-keys` 代替精准绑定；整组保存仍是完整路由列表替换，遗漏兄弟路由会删除它们。

## 回归验证

`go test ./backend/storage ./backend/gateway ./backend/api` 使用本地 SQLite 和模拟供应商，不访问真实渠道。`go test -race` 可检测上述包的并发访问。

MySQL 行锁、大小写敏感快照及旧数据空值回归使用可选的 `UOPS_TEST_MYSQL_DSN`。只指向可丢弃的测试 MySQL（例如本地独立 socket），账号需要建库权限；测试自行建立并删除 `uops_binding_test_` 前缀的隔离数据库，不操作 DSN 中指定的业务库。运行 `go test ./backend/storage -run TestGatewayRoutesMySQL -count=1`；未设置环境变量时这些集成用例跳过。
